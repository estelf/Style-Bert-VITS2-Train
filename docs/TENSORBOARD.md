# TensorBoard で学習状況を見るガイド

学習中の損失の推移や検証発話の合成音声を TensorBoard で確認する方法と、曲線の判断基準をまとめます。実例として `Data/Kotori/models/` のログを想定しています。

## 1. 起動方法

```bash
uv run tensorboard --logdir Data/<モデル名>/models

```

ブラウザで http://localhost:6006 を開きます。このディレクトリには `G_*.pth` などのチェックポイントも一緒にありますが、TensorBoard は `events.out.tfevents.*` ファイルだけを読みます。

ログは同じディレクトリ内の2つのランに分かれています。

| ラン名 | 中身 | 書く場所（コード上） |
|---|---|---|
| `models`（親） | 損失・学習率・勾配ノルムなどのスカラー値 | `train/pipeline.py` の `writer` |
| `models/eval` | `eval_interval`（既定 1000）ステップごとに合成された**試聴用音声** | `writer_eval` |

横軸はすべて `global_step`（学習の総ステップ数）です。学習を再開すると同じディレクトリに新しいイベントファイルが追加され、ステップは途切れずに連続します。

## 2. SCALARS タブ（models ラン）

### まず見るべき主曲線

| タグ | 意味 | 見方 |
|---|---|---|
| `loss/g/total` | 生成器（G）の合計損失 | **最重要**。下がって安定すれば学習が進んでいる |
| `loss/g/mel` | スペクトログラムのL1誤差 | 初期に急降下するのが正常。発音の明瞭度・音質の土台 |
| `loss/d/total` | 判別器（D）の合計損失 | 生成器と綱引きするので G ほど下がらない。急変しなければ OK |

### 内訳（どこが悪いかを切り分ける用）

| タグ | 意味 |
|---|---|
| `loss/g/fm` | 判別器の中間特徴のマッチング誤差。音質の細部に効く。緩やかに低下 |
| `loss/g/dur` | 音素長の回帰誤差。下がればリズムが安定 |
| `loss/g/kl` | KL 正則化。分布が広がりすぎないための制約 |
| `loss/g/0`〜`5` | サブ判別器別（MultiResolution + STFT）の、偽物に対する生成器損失 |
| `loss/d_r/0`〜`5` / `loss/d_g/0`〜`5` | サブ判別器別の本物（real）/ 偽物（gen）に対する損失。特定チャンネルだけ発散していないかの確認用 |

### SLM（WavLM）敵対学習まわり（JP-Extra 固有）

`WD_*.pth` に対応する部分です。

| タグ | 意味 |
|---|---|
| `loss/wd/total` | SLM 判別器の合計損失 |
| `loss/g/lm` / `loss/g/lm_gen` | SLM 特徴のマッチング誤差 / 偽物に対する生成器損失。低下傾向ならスタイル・韻律の学習が進んでいる |
| `grad_norm_wd` | SLM 判別器の勾配ノルム |

### 検証損失（早期停止の監視指標）

`eval_interval` ごとに val.list（held-out 発話。件数は前処理の `--val_ratio`（既定5%）で決まる）で計算される非敵対損失です。敵対損失と違い判別器の状態に依存しないので、**学習の進み・過学習の判定はこっちを見る**（train.list 側と発話が異なるため絶対値は train より高めに出る）。

| タグ | 意味 |
|---|---|
| `val/mel` | 検証データのスペクトログラムL1誤差（c_mel 加重）。**復号音声の全文で測定**（学習のような 0.37秒スライス1点ではない）。早期停止の既定監視対象 |
| `val/dur` / `val/kl` | 検証データの音素長回帰誤差 / KL 正則化項（どちらも全文基準） |
| `val/lm` | 検証データの WavLM feature matching 損失（実音声と生成音声の WavLM 特徴距離。非敵対）。mel のフレーム対応とは別軸で知覚的近さを測る。`use_wavlm_discriminator: false` では出ない |
| `val/total` | mel + dur + kl の合計（後方互換のため lm は含まない。lm を監視したい場合は早期停止の `monitor: "lm"` を明示する） |

`val/mel` が train 側は下がり続けているのに横ばい・上昇に転じたら過学習の兆候。早期停止は既定で有効で、設定とプラトー検出は [GUIDE.md](GUIDE.md) の「早期停止と best checkpoint の自動選定」参照（履歴は `models/eval_history.json` にも残る）。

### 診断用

| タグ | 意味 |
|---|---|
| `learning_rate` | 学習率。warmup 0・既定 1e-4 から毎エポックごく緩やかに減衰（`lr_decay`） |
| `grad_norm_g` / `grad_norm_d` | 勾配ノルム（G は 500 でクリップ）。突発的なスパイクは学習が飛ぶ兆候 |

> **注**: JP-Extra 既定（`use_duration_discriminator: false`）では `loss/dur_disc/*` 系のタグはログされません。

### 曲線の判断基準

- **順調**: `loss/g/total` と `loss/g/mel` が数千ステップのスケールで右肩下がり、やがて緩やかに横ばい
- **収束接近**: 主曲線が横ばいになり、AUDIO タブの試聴でも改善が見られなくなる
- **危険サイン**:
  - 損失が**突然跳ね上がる**（データや勾配の問題で学習が壊れかけている）
  - `loss/d/total` が 0 に張り付く（判別器が生成器に完勝しており、これ以上学べない）
  - `grad_norm_*` に大きなスパイクが頻発する
- 右上の **smoothing スライダー**（既定 0.6）を上げるとノイズがならんで傾向が見やすい。表示切替は「Wall/Step/Epoch」のドロップダウンで Step にしておくとステップ単位で読める

## 3. AUDIO タブ（eval ラン）

`eval_interval` ステップごとに、検証用の数文を合成した音声（`gen/audio_0`〜）と、同じ文の正解音声（`gt/audio_0`〜）がペアでログされます。横軸のステップを進めながら聞き比べるのが使い方です。

**数値よりこちらを信頼する**くらいに思って大丈夫です。目安:

| ステップ | 聞きどころ |
|---|---|
| 数百 | まだ不明瞭・ノイズ混じり。話者の声色だけ出始める |
| 数千 | 明瞭度・話者らしさが出てくる。改善が止まったステップをメモ |
| 以降 | 横ばいなら収束。聞き比べて一番良いステップの重みを選ぶ |

良くなったステップを覚えておき、`model_assets/<モデル名>/<モデル名>_e<epoch>_s<step>.safetensors` のどれを推論に使うか決める参考にします（`app.py` のモデル選択でその safetensors を選べます）。

## 4. 補足

- スペクトログラム・アテンションの画像ログは上流の matplotlib 非互換により撤去済みで、TensorBoard に出るのはスカラーと音声のみです（`train/pipeline.py` のコメント参照）
- 学習曲線だけ見たいときも、学習中なら `--logdir` を向けておけば追記がリアルタイムに反映されます
- 成果物の配置全体は [GUIDE.md](GUIDE.md) の「3. 成果物はどこに生成されるか」を参照
